# PRD — SplashGuard（开屏广告拦截）

版本：v0.1 (MVP)
平台：Android 8.0 (API 26) 及以上
分发：侧载 APK（GitHub Release / 本地安装）

## 1. 产品目标

在不 root、不越狱的前提下，让 Android 设备上的 App 冷启动时**不出现或极快跳过**开屏广告，
同时不破坏 App 的正常功能，不产生任何数据外传。

非目标（明确不做）：
- 不拦截信息流/详情页内的广告（HTTPS 内容层，技术上做不到）
- 不破解会员、不去除付费墙
- 不自动点击广告本体、不伪造曝光
- 不做云端规则同步、不做账号体系

## 2. 核心设计原则

| 原则 | 落地方式 |
|---|---|
| 全部本地 | 无网络上报、无统计 SDK、无账号；规则与日志只在本机 |
| 可解释 | 每条拦截记录写明「哪个 App、哪个域名、命中哪条规则」 |
| 可回退 | 一键关闭拦截，立即恢复原状（无残留系统改动） |
| 最小权限 | 只用 VPN + 可选无障碍，不申请读取短信/联系人/存储 |
| 不越界 | 无障碍只点文本匹配的「跳过/关闭」控件 |

## 3. 用户故事与验收标准

### US-01 开启拦截
**作为** 用户，**我想** 一个开关就开启全部拦截，**以便** 不用理解技术细节。

验收标准：
- AC1 首次点击开关弹出系统 VPN 授权弹窗（`VpnService.prepare`），拒绝后开关回弹到关闭态并提示原因。
- AC2 授权后 3 秒内，通知栏出现 SplashGuard 常驻通知，状态栏出现系统 VPN 钥匙图标。
- AC3 首页状态区显示「运行中」+ 已生效的规则条数。
- AC4 再次点击开关可关闭，关闭后 1 秒内钥匙图标消失，DNS 恢复正常（`dig` 类工具可验证）。

### US-02 拦截生效可验证
**作为** 用户，**我想** 确认它真的在拦截，**以便** 判断是否值得长期开。

验收标准：
- AC1 开启后打开任一走系统 DNS 的 App，首页「最近拦截」列表 5 秒内出现该域名记录。
- AC2 记录包含：时间、App 包名、被拦域名、命中规则。
- AC3 日志只保留最近 200 条，可一键清空，不写入外部存储。

### US-03 分应用控制
**作为** 用户，**我想** 只对指定 App 生效，**以便** 不影响银行/支付类 App。

验收标准：
- AC1 分应用页列出已安装的含桌面入口的应用，显示应用名 + 包名。
- AC2 支持「全部应用」与「仅选中应用」两种模式切换。
- AC3 选择「仅选中应用」且未选任何应用时，不允许保存，提示至少选一个。
- AC4 保存后自动重启隧道，10 秒内新配置生效。

### US-04 自定义规则
**作为** 用户，**我想** 自己加域名，**以便** 对付内置规则没覆盖的 App。

验收标准：
- AC1 规则页支持一行一条、`#` 开头为注释、空行忽略。
- AC2 支持后缀匹配：写 `example.com` 可命中 `a.b.example.com`。
- AC3 保存后立即热生效，无需重启隧道。
- AC4 规则数量实时显示；非法字符（空格、协议头、路径）保存时被拒绝并提示具体行号。

### US-05 拦截方式可选
**作为** 用户，**我想** 选择「返回 0.0.0.0」还是「返回 NXDOMAIN」，**以便** 应对某些
App 在 0.0.0.0 下卡住不前进的问题。

验收标准：
- AC1 设置页提供两种模式单选。
- AC2 切换后立即生效于后续查询。
- AC3 NXDOMAIN 模式下，被拦域名在系统侧表现为「域名不存在」。

### US-06 开机自启
**作为** 用户，**我想** 重启手机后自动恢复拦截，**以便** 不用每次手动开。

验收标准：
- AC1 开关默认开启，重启后 30 秒内服务自动恢复（需此前已授权 VPN）。
- AC2 若系统未授权，重启后不发通知、不崩溃，用户手动开启时再提示。

### US-07 无障碍自动跳过（可选，默认关）
**作为** 用户，**我想** 让它在开屏广告出现时自动点「跳过」，**以便** 补上 DNS 拦不到的场景。

验收标准：
- AC1 默认关闭；开启入口跳转系统无障碍设置页，用户手动勾选后才生效。
- AC2 只在窗口切换后 6 秒内、且距上次点击超过 2 秒时才动作。
- AC3 **只**匹配文本为「跳过 / 跳过广告 / 关闭广告 / Skip / Skip Ad」的控件。
- AC4 控件宽度超过屏幕 60% 时跳过（防止误点整块广告区域）。
- AC5 不点击 SplashGuard 自身界面。
- AC6 关闭开关后服务立即停止响应事件。

### US-08 隐私可见
**作为** 用户，**我想** 确认数据没有外传，**以便** 放心长期使用。

验收标准：
- AC1 设置页内有隐私说明入口，列明申请了哪些权限、为什么。
- AC2 用抓包工具观察：除 DNS 转发（发往用户指定上游）外，无任何其他出站请求。
- AC3 APK 内不含任何第三方统计/广告 SDK。

### US-09 降级模式（私有 DNS 引导）
**作为** 用户，**我想** 在不想开 VPN 时仍有基础拦截，**以便** 灵活取舍。

验收标准：
- AC1 设置页提供「打开系统私有 DNS 设置」按钮，直达系统页面。
- AC2 页面上给出可直接填写的 DoT 主机名示例，并说明其局限（无本地规则、无分应用）。

## 4. 页面结构

```
MainActivity（首页）
├── 状态卡：开关 / 运行状态 / 今日拦截数 / 规则数
├── 快捷入口：分应用 · 规则 · 无障碍
└── 最近拦截列表（RecyclerView，最多 200 条）

SettingsActivity（设置）
├── 拦截模式：0.0.0.0 / NXDOMAIN
├── 上游 DNS（可编辑）
├── 开机自启开关
├── 自定义规则编辑框（多行）
├── 降级模式引导
└── 隐私说明入口

AppPickerActivity（分应用）
└── 应用列表 + 复选 + 模式切换
```

## 5. 验收清单（交付前自检）

- [ ] `./gradlew assembleRelease` 通过，产出可安装 APK
- [ ] 单元测试 `./gradlew test` 全绿（DNS 报文解析/构造、规则匹配）
- [ ] 真机：开启 → 钥匙图标出现 → 打开 App → 日志有记录
- [ ] 真机：关闭 → 钥匙图标消失 → 网络恢复正常
- [ ] 真机：重启后自动恢复
- [ ] 分应用：未选中的 App 不受影响（其域名不被拦）
- [ ] 无障碍：抖音/微博类 App 开屏「跳过」被自动点击，且不误点广告
